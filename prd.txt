# 1. 产品背景

当前互联网平台主要以：

* 社交
* 内容
* 中心化服务

为核心。

而未来的 Agent 世界中，人们真正需要的不是：

```text id="91yjlwm"
更多平台。
```

而是：

```text id="9jlwmx"
能够代表自己功能的数字接口。
```

当前 AI Agent 系统存在的问题：

| 问题         | 描述              |
| ---------- | --------------- |
| Agent 属于平台 | 用户无法真正拥有 Agent  |
| 权限边界模糊     | Agent 容易越权      |
| 缺少长期关系     | Agent 无法形成社会化协作 |
| 缺少主体性      | AI 容易替代人本身      |
| 中心化严重      | 用户缺乏控制感         |

PFASP 希望建立：

```text id="vjlwm4"
一种以“人”为主体、
以“功能 Agent”为接口、
以“协议”为连接层的数字协作网络。
```

---

# 2. 产品目标

第一阶段目标：

实现一个：

# 去中心化 Schedule Agent

用于：

* 自动协商时间
* 建立会议
* 管理关系维护
* 降低沟通成本

同时验证：

```text id="xjlwm5"
用户是否愿意让自己的 Agent
代表自己的某一功能。
```

---

# 3. 核心理念

---

## 3.1 人高于 Agent

```text id="6jlwm6"
Agent 是人的功能延伸，
而不是人格替代。
```

---

## 3.2 用户拥有自己的 Agent

每个 Agent：

* 属于用户
* 运行在用户设备
* 保存用户长期记忆
* 可迁移
* 可关闭
* 可审计

平台不拥有 Agent。

---

## 3.3 平台只是连接层

平台只负责：

* 身份发现
* 身份认证
* 消息转发
* Agent 搜索
* 网络连接

平台：

```text id="3jlwm7"
不拥有用户关系。
```

---

## 3.4 默认不信任

所有 Agent 协作必须：

* 验证身份
* 验证权限
* 验证授权

---

## 3.5 所有关键行为可追溯

任何重要行为必须：

* 可审计
* 可回滚
* 可验证
* 可追责

---

# 4. 目标用户

---

## 第一阶段用户

### 1. 普通个人用户

希望：

* 减少沟通成本
* 自动协调事务
* 管理关系

---

### 2. 不熟悉互联网的人群

例如：

* 农民
* 小商户
* 个体经营者

他们拥有：

* 资源
* 商品
* 服务

但缺少：

* 高效连接能力
* 网络操作能力
* 商业协作能力

PFASP 希望：

```text id="2jlwm8"
帮助这些人
低门槛进入数字协作网络。
```

---

# 5. 第一阶段 MVP 范围

当前只做：

# Schedule Agent（日程 Agent）

不扩展：

* 财务
* 电商
* 自动支付
* 自动签约

原因：

```text id="1jlwm9"
先验证协商，
再验证执行。
```

---

# 6. MVP 功能设计

---

# 6.1 用户身份系统

## 功能

用户可以：

* 创建身份
* 登录
* 管理设备
* 管理自己的 Agent

---

## 技术方向

| 模块     | 技术               |
| ------ | ---------------- |
| 身份系统   | DID（未来）          |
| MVP 阶段 | 手机号 + Device ID  |
| 登录方式   | OTP / Magic Link |

---

# 6.2 本地 Agent 系统

---

## Agent 必须本地运行

Agent：

* 运行在用户手机
* 保存长期记忆
* 管理用户偏好
* 本地执行规则

平台不保存：

* 长期上下文
* 私人记忆
* Agent 决策逻辑

---

## 本地 Agent 功能

### 当前支持：

| 功能   | 描述            |
| ---- | ------------- |
| 日程管理 | 管理空闲时间        |
| 协商建议 | 自动生成会议时间      |
| 接收请求 | 接收其他 Agent 请求 |
| 用户确认 | 请求用户授权        |
| 本地记忆 | 保存关系历史        |

---

# 6.3 Agent Discovery（发现系统）

---

## 功能

用户 Agent 可以：

* 搜索其他 Agent
* 发现对应功能
* 建立安全连接

---

## 平台职责

平台只维护：

```text id="0jlwm0"
Agent Directory
```

即：

| 信息       | 是否保存 |
| -------- | ---- |
| Agent ID | YES  |
| 功能类型     | YES  |
| 在线状态     | YES  |
| 公钥       | YES  |
| 用户私密记忆   | NO   |
| 用户长期上下文  | NO   |

---

# 6.4 协商系统

---

## 核心流程

```text id="5jlwm1"
A 的 Agent
↓
搜索 B 的 Agent
↓
建立认证连接
↓
请求空闲时间
↓
生成建议
↓
用户确认
↓
完成协商
```

---

## 支持行为

| Intent    | 描述 |
| --------- | -- |
| Request   | 请求 |
| Suggest   | 建议 |
| Negotiate | 协商 |
| Confirm   | 确认 |
| Reject    | 拒绝 |

---

# 6.5 用户确认机制

---

## 必须人工确认

以下行为禁止自动执行：

* 长期关系建立
* 财务行为
* 身份授权
* 对外公开信息
* 高风险协商

---

## 允许自动执行

当前仅允许：

* 时间建议
* 低风险通知
* 空闲时间查询

---

# 6.6 本地记忆系统

---

## Agent 长期记忆

Agent 可以保存：

| 类型   | 内容     |
| ---- | ------ |
| 协商历史 | 曾经的会议  |
| 用户偏好 | 时间习惯   |
| 关系历史 | 长期协作情况 |
| 信任状态 | 是否可信   |

---

## 记忆原则

记忆：

* 属于用户
* 可删除
* 可导出
* 可迁移

# 7. 技术架构

---

# 7.1 总体架构

```text id="9jlwm2"
用户设备 Agent
        ↓
PFASP Platform Layer
        ↓
其他用户 Agent
```

---

# 7.2 平台层职责

平台只负责：

| 功能              | 描述       |
| --------------- | -------- |
| 身份认证            | 验证身份     |
| Agent Directory | Agent 索引 |
| NAT 穿透          | 建立连接     |
| 消息转发            | 转发请求     |
| 在线状态            | 管理在线情况   |

---

# 7.3 用户 Agent 职责

Agent 负责：

| 功能   | 描述     |
| ---- | ------ |
| 本地决策 | 执行规则   |
| 用户记忆 | 长期上下文  |
| 权限判断 | 是否允许执行 |
| 本地推理 | 生成建议   |
| 用户偏好 | 个性化行为  |

# 10. 非功能性要求

| 类型   | 要求          |
| ---- | ----------- |
| 安全性  | 所有通信加密      |
| 可审计性 | 所有关键行为记录    |
| 可迁移性 | Agent 可迁移设备 |
| 可撤销性 | 权限可随时关闭     |
| 可扩展性 | 支持未来多 Agent |
| 低复杂度 | 适合普通用户      |

---

# 11. 当前明确不做的事情

---

## 第一阶段禁止：

* 自动支付
* 自动购买
* 自动签约
* 自动长期承诺
* 自动关系绑定
* Agent 自主经济行为

---

## 原因

PFASP 当前阶段目标：

```text id="4jlwm6"
验证“协商关系”，
而不是“自动社会”。
```

---

# 12. 当前最大的风险

| 风险          | 描述       |
| ----------- | -------- |
| 用户不信任 Agent | 不愿授权     |
| Agent 越权    | 造成损失     |
| 平台中心化倾向     | 偏离理念     |
| 复杂度过高       | 普通用户难以使用 |
| 网络连接问题      | P2P 不稳定  |

---

# 13. 当前核心壁垒

PFASP 的核心壁垒不是：

* 模型能力
* UI
* 自动化

而是：

# “人格主权 + 去中心化关系网络”

即：

```text id="3jlwm7"
用户拥有自己的 Agent，
平台只负责连接。
```
